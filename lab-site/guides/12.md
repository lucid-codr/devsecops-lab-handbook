# Azure infrastructure deployment with Terraform
> Windows · PowerShell · Terraform · Azure CLI · OpenSSH · Azure subscription with deployment permissions

## Prepare your subscription and project
Use an approved lab subscription with VM quota and budget. This lab provisions billable resources. Open PowerShell in lab-12. Confirm the active subscription and switch with az account set --subscription YOUR_LAB_SUBSCRIPTION_ID if needed.
~~~PowerShell
terraform version
az version
az login
az account show --query "{name:name,id:id}" -o table
~~~
~~~PowerShell
$env:ARM_SUBSCRIPTION_ID = az account show --query id -o tsv
ssh-keygen -t rsa -b 4096 -f lab-key -C devsecops-exp12
Copy-Item terraform.tfvars.example terraform.tfvars
~~~
Use a passphrase and keep lab-key private. Edit terraform.tfvars before continuing. Set a unique lab prefix, a globally unique lowercase alphanumeric storage account name of 3–24 characters, and your current public IPv4 address with /32. The provided address is an example. If Central India or the selected VM size is unavailable, add location and vm_size overrides for an allowed region and SKU.
@file terraform.tfvars.example

## Review and plan
main.tf provisions a resource group, virtual network, subnet, public IP, network security group, network interface, network association, storage account, and Linux VM. The inbound SSH rule uses the /32 you set.
@file main.tf
@file variables.tf
@file .gitignore
~~~PowerShell
terraform init
terraform validate
terraform plan -out=lab.tfplan
terraform show lab.tfplan
~~~
Confirm the subscription, nine expected Azure resources, and scope of the changes. If you only need to explain infrastructure as code, the reviewed plan is a demonstration checkpoint. Continue below to show live resources.

## Apply and verify
~~~PowerShell
terraform apply lab.tfplan
terraform state list
terraform output -raw public_ip_address
~~~
Replace REPLACE_WITH_LAB_PREFIX with the exact lab_prefix from terraform.tfvars.
~~~PowerShell
$prefix = "REPLACE_WITH_LAB_PREFIX"
az resource list --resource-group "$prefix-rg" --query "[].{Name:name,Type:type}" -o table
az vm show -g "$prefix-rg" -n "$prefix-vm" --show-details --query "{Name:name,State:powerState,Size:hardwareProfile.vmSize}" -o table
~~~

## Show the professor
Show the Terraform plan, the nine entries in state, and the VM power state in Azure. Explain how the subnet, network interface, and network security group connect to the VM.

## Destroy the resources
Keep the original working directory and Terraform state until cleanup completes. Inspect the destroy plan and confirm removal of the lab resources at the prompt. Set $prefix to the lab prefix from terraform.tfvars if you skipped the verification step. Verify the resource group is gone.
~~~PowerShell
terraform destroy
az group exists --name "$prefix-rg"
Remove-Item Env:ARM_SUBSCRIPTION_ID
~~~
If a deployment was partially successful, keep the state and use the same cleanup process. If Azure reports insufficient quota or an unavailable SKU, check the region and allowed sizes with your subscription administrator.
