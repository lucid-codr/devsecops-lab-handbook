# Dependency vulnerability scanning with Snyk
> Windows · PowerShell · Node.js LTS · Snyk account

## Install the sample dependency and CLI
Extract lab-09 and open PowerShell there. The starter uses an older lodash release for a dependency-scanning exercise. Scan the dependency manifest and lockfile.
@file package.json
~~~PowerShell
node --version
npm.cmd install --ignore-scripts
npm.cmd install -g snyk
snyk.cmd --version
snyk.cmd auth
~~~
Complete authentication in the browser, then return to PowerShell.

## Scan and record the baseline
~~~PowerShell
npm.cmd ls lodash
snyk.cmd test
$LASTEXITCODE
~~~
The report lists affected packages, finding severity, and remediation advice. A scan with findings can exit with code 1. A scan error is reported separately. [Snyk test exit codes](https://docs.snyk.io/developer-tools/snyk-cli/commands/test)

## Upgrade and rescan
Choose the patched release recommended by the scan. Replace REPLACE_WITH_PATCHED_VERSION before running. Save the second scan result and compare findings using the same Snyk organization settings.
~~~PowerShell
npm.cmd install lodash@REPLACE_WITH_PATCHED_VERSION --save-exact --ignore-scripts
npm.cmd ls lodash
snyk.cmd test
~~~

## Show the professor
Compare the manifest version and scan findings before and after remediation. Point out the dependency path and the suggested fixed version.

## Cleanup and troubleshooting
If the scanner cannot authenticate, retry snyk.cmd auth and verify your account can run Open Source tests. Remove node_modules or delete the lab folder when done. Keep the lockfile and redacted scan output if needed for evidence.
